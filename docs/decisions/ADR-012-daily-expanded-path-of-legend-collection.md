# ADR-012：每天执行 20 万场传奇之路扩散采集

- 状态：已采用
- 日期：2026-08-01
- 修订：ADR-009 的日采/周采节奏

## 背景

只抓排行榜前 1000 名本人的日采通常只能得到约两万场短日志样本。虽然它能提高顶尖玩家
样本占比，但对完整卡组、完整配置和精确对阵的覆盖仍然稀疏。现有扩散采集已经具备严格
传奇之路闭环、稳定对局 ID、全库去重、低速限流、断点续传和 35 天真实窗口，因此可以在
不重复计权的前提下每天扩大高质量观察池。

## 决策

- 上海时区每天 03:00 固定运行 `weekly_expanded`，目标为批内 200,000 场唯一对局。
- `weekly_expanded` 名称为历史兼容标识，不再表示每周一次。
- 每批冻结全球传奇之路前 1000 名，先完成直接采集，再只沿已接受的 `pathOfLegend` 对局扩散。
- `daily_ranked` 代码仅作为历史兼容能力保留，不进入计划任务、默认入口或操作手册。
- 跨批重复对局只新增观察关系，不重复写入事实，也不重复计权。
- 35 天窗口内扩散批次不设数量上限；事实只在最后一个有效观察关系过期后删除。
- 成功发布、API/RAG 对齐并完成服务验收后，精确删除本批成功工作区，避免采集副本长期占盘。

## 结果

- 完整卡组、觉醒、精英、塔楼和低频对阵得到更高覆盖。
- 每日官方 API 请求、采集时间、本地事实库、三十范围统计和本机 embedding 成本明显增加。
- 20 GiB 启动阈值、单写锁、并发 1、默认每秒 1 请求及 429 失败门槛继续生效。
- 数据源、玩家 tag、运行日志、SQLite、Qdrant 和导出均保持本地私有，不进入远程仓库。
