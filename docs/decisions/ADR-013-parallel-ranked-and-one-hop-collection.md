# ADR-013: 双通道抓取与单写者合并

## 状态

已采用

## 日期

2026-08-10

## 背景

`daily_ranked` 每两小时抓取全球传奇之路前 1000 名，单次通常运行 1.5 小时以上。若扩展采集只能等待核心采集结束，每天最多获得约 6 小时扩展窗口，无法稳定完成一层对手扩展。原实现还在整个网络抓取期间持有 `corpus.sqlite` 写锁，因此增加第二枚 API Key 也不能形成并行吞吐。

同时必须保持以下边界：核心采集优先、传奇之路严格过滤、完整卡组契约、全局 `battle_id` 去重、失败才发送 PushPlus、凭据不进入命令行和日志，以及本机内存和磁盘占用有硬上限。

## 决策

- `SUPERCELL_API_TOKENS` 提供两个槽位：槽位 0 用于 `daily_ranked`，槽位 1 用于 `weekly_expanded`。旧 `SUPERCELL_API_TOKEN` 只作为核心通道的单 Key 兼容入口。
- 两个通道可以同时执行网络抓取，但分别写入 `data/rolling_lanes/<mode>/active` 下的磁盘工作区。
- 网络抓取不持有主库写锁。抓取完成后，通道最多等待 30 分钟获取 `data/corpus/writer.lock`，再串行执行导入、验证、35 天保留策略和快照发布。
- 扩展只从本轮排行榜种子产生第一层对手；扩展玩家不会继续生成下一层队列。
- 工作区继续使用 SQLite 流式写入，并发数保持 1。核心工作区上限为 512 MiB，扩展工作区上限为 4 GiB，两个新通道合计上限为 5 GiB。
- 正式采集不再导出重复的 `raw_battles.jsonl` 暂存副本。导入结束后无论批次接受或拒绝，活动工作区都会删除；进程中断时保留状态并在下一次触发中断点续采。
- 核心任务每两小时触发。扩展任务每 15 分钟触发且使用 Task Scheduler `IgnoreNew`，从而在上一实例运行时不会叠加第二个进程。
- 每个通道写独立状态文件；失败通知包含通道、批次、主库累计量、暂存占用、磁盘余量和预检结果，但不包含 Token、玩家 Tag、原始对局或完整日志。

## 备选方案

### 在核心采集结束后运行扩展

每天只有约 6 小时可用，吞吐不足，因此放弃。

### 两个进程直接写同一个主库

SQLite 仍是单写者，且发布过程需要一致快照。并发写会增加锁冲突和部分发布风险，因此放弃。

### 提高单通道 HTTP 并发

可能改变排行榜顺序、公平限流和失败模式，不能替代独立通道；当前仍保持每个 Key 每秒 1 请求、并发 1。

## 后果

- 两枚 Key 的网络时间可以重叠，核心两小时节奏不再给扩展通道只留下空档时间。
- 主库仍只有一个写入者，现有全局事实去重和发布一致性保持不变。
- 运行时最多有两个受控 Python 抓取进程，磁盘工作区和单次内存批量均有上限。
- 如果第二枚 Key 缺失、IP 不在白名单、工作区超限或主库锁连续 30 分钟不可用，对应通道失败并发送 PushPlus；另一通道不受影响。

## 回滚

禁用 `ClashRoyale-Expanded-Continuous` 即可立即退回单通道采集。核心任务可继续使用槽位 0；如需完全回滚，禁用两个新任务并恢复旧的核心计划任务。主库 schema 未改变，不需要数据迁移或回滚。
