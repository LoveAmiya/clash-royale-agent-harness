# ADR-011：三十范围、完整配置实体与预计算环境差分

- 状态：已采用
- 日期：2026-08-01
- 修订：ADR-009 的十范围发布层、ADR-010 的结构化物化合同

## 背景

最近 7 天与累计 35 天无法直接回答“上一周发生了什么变化”，让模型临时比较大量快照既浪费上下文，也容易跨口径引用。完整配置原始数据已经能区分塔楼、普通、觉醒和精英状态，但旧接口只将完整配置用于卡组，无法进行实体排名、单体查询和自由问答。

## 决策

发布层扩展为六个时间窗口乘五个层级，共三十个 `dataset_scope`：`7d`、`d7_14`、`d14_21`、`d21_28`、`d28_35`、`35d`，以及 `top_100/top_200/top_500/top_1000/all`。窗口仍按成功批次 `completed_at` 计算。空历史分段保持明确未就绪，不以当前数据回填。

结构化 schema 5 新增 `loadout_entity_stats`。实体 ID 固定为 `card:{official_card_id}:ordinary|evolution|elite` 和 `tower:{official_tower_id}`。只统计完整载荷中实际出现的实体，旧基础八卡记录不得伪造普通、觉醒、精英或塔楼实体。

相邻七天分段预计算 `meta_delta`，覆盖实体、卡组、体系以及基础八卡与完整配置分化。实体和体系每侧至少 200 次、卡组至少 30 场；显著性同时使用 Wilson 95% 区间、样本门槛与绝对变化门槛。RAG 仅索引这些聚合证据，不索引单场对局。

所有页面显式传递 `dataset_scope` 与全局 `entity_mode`。完整配置不可用时返回 `ENTITY_STATS_NOT_READY` 或前端置灰，不允许静默回退。旧十范围活动组可继续读取已有范围，但新增历史范围、实体统计和差分保持未就绪，直到下一代快照组完成物化。

完整配置能力分为 `complete_loadout_ready` 与 `entity_stats_ready`：前者证明完整载荷/卡组统计存在，后者证明统一实体表已经物化。全站普通/觉醒/精英/塔楼入口要求两者同时成立，避免迁移期把基础八卡统计误标为完整配置统计。

RAG 综合仍执行严格数值与引用校验。模型必须原样引用证据数字；本地流式和非流式质量门会删除未受支持的数值句、保留其余已验证内容并标注边界，不为修复再次调用模型。最终校验失败时返回带验证来源的安全拒答，不再把 `GroundingValidationError` 暴露成通用生成失败。

观测层保留现有 `trace_id`，增加 `parser/retrieval/rerank/synthesis/review/validation` 标准 span 名称。确定性、检索、引用、故障注入和实时解析报告各自附带统一 `scorecard`，也可由 `python -m evaluation.scorecard` 离线聚合既有 JSON 报告。维度固定为 `snapshot_group_id/snapshot_id/dataset_scope/deck_mode/entity_mode/model/prompt_hash`，缺失测量通过 `metric_coverage` 明示，不把“没有测量”冒充为实际零值。问题只记录 SHA-256 与长度，玩家标签和正文不进入 span、统一报告或日志。

## 后果

- 同一次事实采集支持当前、历史和累计观察，不增加 Supercell 请求或云端模型费用。
- 三十范围和实体文档增加本地统计、磁盘索引与预热时间，因此顺序构建并限制 BM25 缓存。
- 完整配置样本更稀疏，所有接口仍必须返回实际样本量、置信度和低样本警告。
- 环境变化问答优先读取 `meta_delta`，模型只综合已物化证据，不自行拼接跨窗口原始统计。
- 采集器合同不因本次发布层升级而改变。
