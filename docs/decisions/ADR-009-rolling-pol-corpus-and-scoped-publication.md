# ADR-009：滚动传奇之路事实库与范围化发布

- 状态：部分被 ADR-011 与 ADR-012 取代
- 日期：2026-07-30

## 背景

单份每周 20 万场快照无法同时表达顶尖玩家短期环境、全量扩散样本和较长观察窗口。物理复制多个原始 JSON 会重复占用磁盘，并使去重、过期和统计口径容易分叉。让模型从问题里推断数据范围也会增加路由不确定性。

## 决策

采用一份 SQLite 滚动事实库：`battles` 保存唯一事实，`battle_observations` 保存批次、观察者、名次和来源。日采只抓排行榜本人；周采从排行榜有效对局闭环扩散。所有事实最多由有效观察关系保留 35 天。35 天窗口内的周采不设批次数量上限，允许环境剧变时临时加采；日采仍最多保留 35 个批次。

发布层提供十个固定 `dataset_scope`。结构化统计共用一份带范围键的 SQLite；RAG 使用聚合文档和一份带范围 payload 的本地 Qdrant。前端显式选择范围，旧客户端默认 `7d_all`，非法或未就绪范围禁止自动回退。

事实写入、过期和发布由单写进程及文件锁保护。十个范围全部通过质量门后才更新活动指针，保留当前和上一代快照组。

## 结果

- 跨日、跨周和正反双方观察不再重复计权，但重新观察会延长事实有效期。
- 临时周采不会因为第 6 个批次到来而提前淘汰仍在 35 天窗口内的数据；代价是磁盘和物化时间随临时周采次数增长。
- 高排名观察过期后，最小名次动态重算；扩散观察永远不能进入 `top_N`。
- 业务 API 不承担读取百万级事实表的延迟和锁风险。
- 本地存储与后处理增加，但不增加云端模型或 embedding 费用。
- 首个新周采完成前，旧快照保持在线并可回滚。

## 后续修订

- ADR-011 将十个范围扩展为三十个范围，并增加完整配置实体和环境差分。
- ADR-012 取消生产日采，改为每天执行 20 万场扩散批次；本 ADR 中的日采/周采节奏仅保留为历史背景。
